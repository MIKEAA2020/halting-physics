solver provenance, extends the dense-influence family to n=17 and n=18

## 2. Dense-chain extension to n=17 and n=18 (phase 4 extension)


The four extension cases (dense-chain at 17 and 18 springs, both
observation variants) are generated by the recorded phase-4 driver
`mechanics_benchmarks.run_case` with the same settings as the recorded
dense-chain cases: full relation enumeration with no cap, deterministic
minimum-fill elimination validated by the tree-decomposition verifier,
certified DP with certificate emission, and policy reconstruction.
Generation is checkpointed per case because the environment terminates
long-running sessions. Recorded gate
(`reports/mechanics_dense_extension.json`):

```json
{
  "cases": 4,
  "row_batches_verified": 4,
  "decompositions_verified": 4,
  "dp_certificates_verified": 3,
  "policies_verified": 1,
  "refutations_certified": 2,
  "dp_memory_limit_cases": 1,
  "missing_cases": 0
}
```

Per case: n=17 same (width 16, 17 bags, relation tables up to 139 tuples)
is refuted with a verified `DP-REFUTATION` (120.2 MB certificate); n=17
split (width 16, 34 variables) is solved with a verified `DP-OPTIMUM` and
policy (243.2 MB); n=18 same (width 17, relation tables up to 162 tuples)
is refuted with a verified `DP-REFUTATION` (252.5 MB); n=18 split
(width 17, 36 variables) exceeds the machine's physical memory during
in-process certificate emission and is recorded as `DP-MEMORY-LIMIT`: the
generator process was killed by the global OOM killer at exit code 137
with about 3.75 GiB resident (kernel log: `Out of memory: Killed process
8298 (python3) total-vm:3816532kB, anon-rss:3750608kB`). Its model,
certified row batch, instance, and validated decomposition are archived;
the failed-case record
`reports/dense_ext_gen_dense_18_split_FAILED.json` states that no DP
certificate is producible for this case in this environment.

The seven agreements exclude the three verified satisfiable answers on

Recorded observations, per-instance and without a superiority claim:
minisat exceeds the 60-second limit on all four extension instances; CP-SAT
returns unknown within its limit on the three unsatisfiable or
encoding-heaviest variants (its n=17/18 same and split encodings are

of the budget); kissat and z3 answer the n=17 variants in seconds and
kissat is the only solver answering the unsatisfiable n=18 variant within
the limit (52.18 s); on the satisfiable n=18 split variant, kissat, z3,
and HiGHS return models that verify natively as policies while the
certificate-emitting native DP cannot complete within the 3 GiB cap. The
native certificates grow as 2^n (120.2, 243.2, and 252.5 MB at n=17/18),
which remains the recorded cost of the certificate-emitting pipeline and
the honest boundary of the dense family in this artifact.

## 4. Harness accounting audit and root-cause fix

The v6 manuscript footnote and plan v20 item 6 claimed that the recorded
summary counters (34 SAT, 33 UNSAT, 3 inconclusive, 67 agreements) were
inconsistent with the per-instance records, hypothesizing a CP-SAT
`UNKNOWN` run on the unsatisfiable dense-16 variant counted among the
cross-checked unsatisfiable answers, and proposed a "corrected accounting"
of 32 UNSAT, 4 inconclusive, and 66 agreements. The forensic audit of this
round refutes that claim on four independent grounds:

1. **Per-instance records.** In the recorded artifact the CP-SAT run on
   dense-chain n=16 same has classification `UNSAT`, cross-check
   `VERIFIED-UNSAT` (against the verified native `DP-REFUTATION`), and a
   49.5 s median; there are exactly three non-answers (minisat on both
   dense-16 variants, HiGHS on the unsatisfiable one). The recorded
   counters 34+33+3 = 70 are arithmetically consistent with the
   per-instance records. `audit_sweep_summary.py` verifies the same
   consistency for the earlier external-baseline sweep (95/25/0/120) and
   for the v2 replication.
2. **Replication.** The version-exact replication answers the same
   instance `UNSAT` at a 50.3 s median with the same verified cross-check.
3. **Code-level impossibility.** `cpsat_runner.py` emits
   `CERTIFIED-UNSAT-EXTERNAL` only for the solver status `INFEASIBLE`;
   `UNKNOWN` maps to `INCONCLUSIVE` and a `None` classification. No
   `UNSAT`/`UNKNOWN` bucketing branch exists in any counter.
4. **Artifact provenance.** The recorded
   `reports/mechanics_external_baseline_sweep.json` is byte-identical
   (SHA-256 `acd666e340da4fb08b58f727b2259a6eba5749b76fd9d2eb6440f3cfec6c4226`)
   across the release-v4 archive, the recorded-reports extraction, the
   live prototype, and the repository; it has never been regenerated.

The root-cause remediation therefore lives in the harness code and the
manuscript, not in a patched artifact:

- `external_baseline_sweep.py`, `mechanics_baseline_sweep.py`, and
  `dense_extension_sweep.py` now gate the `status_agreement_with_native`
  counter on verified cross-check evidence: an external run counts as an
  agreement only if its classification matches the native status and its
  cross-check status is `VERIFIED-SAT` or `VERIFIED-UNSAT`. This closes the
  latent over-counting hole (a rejected or evidence-free answer could
  previously be counted as an agreement) and makes the identity
  agreement = verified SAT + verified UNSAT structural whenever every
  native run is conclusive.
- `verify_accounting_fix.py` proves the change semantics-preserving on
  every recorded sweep: recorded = old semantics = fixed semantics
  (120/120, 67/67, 67/67), and the identity holds.
- The recorded JSON is deliberately **not** regenerated: it is already
  consistent, and regenerating it would overwrite the user's original
  artifact, contrary to the version discipline.

```text

python3 dense_extension_generate.py --assemble
python3 dense_extension_sweep.py --cases <key> --solvers <names> (per unit)

python3 build_dense_ext_manifest.py
python3 audit_sweep_summary.py reports/mechanics_external_baseline_sweep_v2.json

python3 crosscheck_table3.py
```

`make reproduce` continues to run the recorded gates unchanged; the
extension studies are separate commands because their full certificate
emissions exceed the memory of the recording environment when run
together.
